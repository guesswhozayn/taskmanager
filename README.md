# My Awesome Task Manager
Video Demo: https://youtu.be/QMTRK8rGvSE?si=a74YhAZ801wfOCaQ

# Description:
This is "My Awesome Task Manager," a personal web-based task management application developed as the final project for Harvard's CS50's Web Programming with Python and JavaScript. It provides users with a simple yet effective way to organize their daily tasks, track their progress, and stay on top of their to-do lists. The application is designed with a focus on user experience, security, and responsiveness.

# Core Features:

User Authentication: Secure registration, login, and logout functionalities, ensuring each user's tasks are private.

Task Creation: Users can easily add new tasks with a title and an optional detailed description.

Task Listing: Displays all tasks associated with the logged-in user, ordered by creation date (newest first).

Task Status Toggle: Tasks can be marked as complete or incomplete with a single click, providing immediate visual feedback (implemented with AJAX for a smooth user experience).

Task Deletion: Users can permanently remove tasks they no longer need (also implemented with AJAX).

Optional Task Details: Support for adding optional due dates and priority levels (Low, Medium, High) to tasks.

Responsive Design: The application's interface adapts gracefully to various screen sizes, from desktops to mobile devices, thanks to Bootstrap 5.

# Technologies Used:

Backend: Python 3, Django (Web Framework)

Database: SQLite3 (default for development, easily configurable for PostgreSQL/MySQL)

Frontend: HTML5, CSS3 (with Bootstrap 5), JavaScript (ES6+ with Fetch API for AJAX)

# File Breakdown & Design Choices:

The project follows Django's MVT (Model-View-Template) architectural pattern, organizing code logically for maintainability and scalability.

taskmanager_project/ (Main Project Directory):

settings.py: Contains the core configuration for the Django project, including INSTALLED_APPS (where tasks and django.contrib.humanize are registered), TEMPLATES directory configuration, STATIC_URL, STATICFILES_DIRS, and LOGIN_REDIRECT_URL. The MESSAGE_STORAGE is also configured for displaying user feedback.

urls.py: The main URL dispatcher for the entire project. It includes URLs for the Django admin, authentication (login, logout, register), and delegates all task-related URLs to the tasks app's urls.py. This modular approach keeps URL routing clean.

wsgi.py, asgi.py: Entry points for web servers.

__init__.py: Marks the directory as a Python package.

tasks/ (Task Application Directory):

models.py: Defines the Task database model. Each Task is linked to a User via a ForeignKey, ensuring data integrity and user-specific task management. Fields like title, description, completed, created_at, due_date, and priority are defined, with appropriate defaults and options for nullability/blankness. The __str__ method provides a human-readable representation of a task.

views.py: Contains the Python logic for handling HTTP requests and rendering responses.

register: Handles user registration, validating input (password match, unique username) using RegistrationForm and creating new User objects.

task_list: Displays all tasks for the currently authenticated user. It fetches tasks from the database and passes them to the template along with an empty TaskForm for adding new tasks. The @login_required decorator ensures only authenticated users can access this page.

add_task: Processes POST requests for adding new tasks. It validates the form data using TaskForm, assigns the current user to the task, and saves it to the database.

toggle_task: An AJAX endpoint (@require_POST) that toggles a task's completed status. It fetches the specific task (ensuring it belongs to the logged-in user) and updates its status in the database, returning a JSON response.

delete_task: An AJAX endpoint (@require_POST) that deletes a task. It fetches the task (user-owned) and removes it from the database, returning a JSON response.

urls.py: Defines URL patterns specific to the tasks application, mapping them to the corresponding views (task_list, add_task, toggle_task, delete_task).

forms.py: Contains Django Form and ModelForm classes for handling user input.

RegistrationForm: A custom form for user registration, including fields for username, password, and confirmation, with custom validation for password matching and unique usernames.

TaskForm: A ModelForm linked to the Task model, simplifying the creation and validation of task data. It specifies which model fields to include and customizes their widgets for better Bootstrap integration.

admin.py: Registers the Task model with the Django administrative interface, allowing easy data management by superusers.

migrations/: Directory containing database migration files generated by Django to manage schema changes.

templates/ (HTML Templates Directory):

base.html: The base template for the entire application. It includes common HTML structure, Bootstrap CSS/JS, a responsive navigation bar (displaying login/logout links based on user authentication status), and a message display area for Django's messages framework. It uses Django's template inheritance ({% block %}) to allow child templates to inject their specific content.

registration/login.html: Template for the user login page, extending base.html. It uses Django's built-in AuthenticationForm (rendered via form.as_p or manual field rendering).

registration/register.html: Template for the user registration page, extending base.html. It uses the custom RegistrationForm to collect user details.

tasks/task_list.html: The main task display page, extending base.html. It renders the TaskForm for adding new tasks and iterates through the user's tasks, displaying their details. It includes the checkboxes and delete buttons with data-task-id attributes for JavaScript interaction.

static/ (Static Files Directory):

css/style.css: Contains custom CSS rules to enhance the application's appearance and override Bootstrap defaults if needed.

js/script.js: Contains the client-side JavaScript logic. This file handles the AJAX requests for toggle_task and delete_task using the Fetch API. It dynamically updates the UI (e.g., strikethrough text, changing list item color, removing deleted tasks) without requiring a full page reload, significantly improving user experience. It also includes a getCookie helper function for retrieving the CSRF token. Event listeners are attached after the DOM is loaded to ensure interactivity.

# Design Choices & Challenges:

The decision to use Django was driven by its "batteries-included" philosophy, providing robust features like ORM, admin interface, and authentication out-of-the-box, which are essential for a full-stack web application. Bootstrap 5 was chosen for rapid development of a responsive and aesthetically pleasing UI.

A key design decision was to implement task toggling and deletion using AJAX (Asynchronous JavaScript and XML). Initially, these actions would cause a full page reload, which is jarring for the user. By using JavaScript's Fetch API to send POST requests to dedicated Django views (toggle_task, delete_task) and then dynamically updating the DOM, the user experience became much smoother and more modern. This required careful handling of CSRF tokens in JavaScript to maintain security.

Ensuring user-specific data was a primary concern. The ForeignKey relationship in the Task model and the request.user filtering in views (Task.objects.filter(user=request.user)) were crucial to prevent users from accessing or modifying other users' tasks.

# How to Run the Project Locally:

## Create and Activate a Virtual Environment:

It's highly recommended to use a virtual environment to manage dependencies.

python3 -m venv venv

### On macOS/Linux:

source venv/bin/activate

### On Windows (Command Prompt):

venv\Scripts\activate

On Windows (PowerShell):

.\venv\Scripts\Activate.ps1

## Install Dependencies:

Install all required Python packages using pip.

pip install -r requirements.txt

(If you haven't created requirements.txt yet, run pip freeze > requirements.txt first, while your venv is active).

## Apply Database Migrations:

This creates the necessary database tables for Django's built-in apps and your Task model.

python manage.py migrate

## Create a Superuser (for Admin Access):

This allows you to access Django's administrative interface.

python manage.py createsuperuser

Follow the prompts to set a username, email, and password.

## Start the Development Server:

python manage.py runserver

You should see output indicating the server is running, typically at http://127.0.0.1:8000/.

## Access the Application:

Open your web browser and go to http://127.0.0.1:8000/.

You will be redirected to the login page.

Click "Register" to create a new user account.

Log in with your newly created credentials.

You can then start adding and managing your tasks!

You can also explore the Django admin interface at http://127.0.0.1:8000/admin/ using your superuser credentials.
